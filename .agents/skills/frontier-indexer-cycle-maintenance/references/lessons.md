# Lessons from the Cycle 6 → Cycle 7 change

Historical evidence: `openspec/changes/archive/2026-10-09-upgrade-frontier-indexer-cycle-7/validation.md`. These observations are examples, not defaults for future cycles.

- **SQL stdin was missing.** `podman run` without `-i` silently discarded the SQL heredoc. `psql` exited successfully, so a generation marker could be published without resetting the schema. Real container testing caught retained watermarks. Preserve stdin forwarding and a regression that requires actual table removal.
- **Readiness was not authentication.** The old startup graph reset before database preflight. Preserve readiness → authenticated preflight → reset → indexer, including credential-repair testing without logging passwords.
- **Ordering alone cannot stop an old writer.** `Before=` does not prove an already-running process has stopped. Managed Ansible stop-before-switch plus a reset refusal for a surviving writer covered this transition.
- **Any unequal marker was unsafe.** A downgrade could erase new data. Treat missing/older/equal/stale/invalid markers distinctly; null cannot bypass an existing marker. Test wide/invalid generations, concurrent starts, SQL failure, durable publication failure and successful retry.
- **A marker alone is not disaster recovery.** Publish it only after committed SQL, serialize through fsync/atomic replacement, and coordinate database/marker restores. Do not promise rollback restores discarded data.
- **Schema-limited is not dependency-limited.** PostgreSQL CASCADE can remove objects in other schemas. Inventory before every cycle. In Cycle 7, the only sampled application client was Frontier Indexer, public was empty and all application hypertables/bookkeeping were in indexer; that does not prove future cycles remain exclusive.
- **No extra artifacts means no new deletion.** The Cycle 7 cleanup allowlist was empty beyond the schema. Cluster, secrets, monitoring history and project archives were infrastructure, not old-cycle caches.
- **Targeted tags were still host-wide.** The Frontier tag invoked a full Habiki NixOS switch and the role's existing restart loop for all active Podman services. Approval and downtime coordination must describe that scope accurately.
- **Metrics had a restart-readiness race.** Querying immediately after a database connection appeared caused a connection refusal before the metric listener opened. Subsequent skill testing also showed that a reachable endpoint can precede lazy processor/concurrency metric initialization. Wait for the endpoint and required dashboard metric families, then check Prometheus; bounded failure still detects genuinely missing/renamed metrics.
- **Raw deployment logs wasted context.** Ansible's restart debug included huge full systemd status dictionaries. Reduce those streams to fixed phase names, recap counters and final checks; do not reread full debug payloads.
- **A short SSH deadline produced a false access blocker.** A later read-only retry with a bounded longer deadline succeeded. Report uncertainty, never disable host-key checks/authentication, and get guidance rather than treating connection failure as permission to skip live inventory.
- **A bootstrap socket is not network readiness.** The reusable container test initially observed the temporary PostgreSQL init server's Unix socket, then failed authenticated preflight before TCP was listening. Match production's pg_isready probe from the indexer network, rather than adding an arbitrary sleep or weakening authentication checks.
- **Normalize database client addresses.** PostgreSQL inet text can include `/32` or `/128`, unlike Podman's plain IPs. Use PostgreSQL `host(client_addr)` before classifying a client as external; do not suppress real external-client review flags.
- **Image defaults matter.** Update both host declaration and reusable module default. Validate latest applicable stable release, release age, registry hashes, platform, compiled contracts and source metadata rather than guessing from a mutable tag or model knowledge.
