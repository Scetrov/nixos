## Context

Dependency-Track is private and unreachable from GitHub-hosted runners. Issue #27 separates SBOM generation from ingestion: trusted workflows publish artifacts, and a private host fetches them outbound. Existing NixOS/Ansible automation handles Dependency-Track containers and service configuration; all OpenTofu operations must use `scripts/tofu.sh`. Forgejo mirror eligibility does not establish trust in workflow artifacts.

## Goals / Non-Goals

**Goals:** Secure, idempotent, outbound-only artifact retrieval and upload with explicit project/version mapping, durable accepted-upload checkpoints, and actionable transfer recovery.

**Non-Goals:** Public API exposure, VPN/tunnel, a CI runner on the private host, executing repository code or generating SBOMs in the collector, SBOM-controlled project creation, automatic remediation, mandatory attestations, verifying Dependency-Track's internal processing, or coupling discovery policy to #26.

## Decisions

1. **One complete vertical slice first.** Start with one trusted repo, workflow ID, successful run/ref, versioned CycloneDX JSON artifact contract, and pre-created Dependency-Track project UUID. Generalize only through explicit configuration records, not a shared platform/framework.
2. **Authenticate provenance before payload use.** Match repository identity, trusted workflow identity, permitted event/ref, successful conclusion, and artifact name against GitHub API metadata. Default to protected-branch push and permitted release/tag workflows; reject pull-request/untrusted-fork production. Account for workflow attempts and reruns. Stronger attestations are optional later hardening, not an MVP dependency; document that API metadata does not protect against compromise of an allowed workflow.
3. **Versioned producer contract.** Define artifact name/version and exactly one expected JSON path, supported CycloneDX schema versions, generation trigger, upload cadence, and retention exceeding the supported polling outage. Use existing producer workflows if compliant; otherwise document and apply the smallest workflow change only in an authorized source repository. Pin new actions to full commit hashes and resolve applicable releases before implementation. Never grant producer jobs Dependency-Track credentials.
4. **Treat archives and JSON as hostile.** Bound download bytes, expanded bytes, file count, JSON complexity, execution time, and disk use. Reject absolute/traversal paths, symlinks, duplicate/ambiguous payloads, unsupported formats, invalid schemas, and inconsistent available artifact digests. Prefer streaming the single approved member without general extraction. Package schemas locally with verified integrity; disable remote schema resolution. Execute no scripts, build tools, or commands from artifacts.
5. **Trusted destination mapping.** Configure repository/ref-to-project UUID/version mappings outside payloads and use `autoCreate=false` by default. The first slice has a pre-created target; later release versions require explicit pre-provisioning or separately approved constrained provisioning through existing service automation. SBOM fields cannot select arbitrary projects. A rolling development project gets only newer authorized inventories; reject stale rollback uploads. Document that BOM ingestion updates that project's dependency inventory rather than merging arbitrary historical snapshots.
6. **Durable upload checkpoints.** Key records by stable repo ID, workflow/run attempt, artifact ID/digest, and target UUID/version. Persist accepted upload and the returned tracking token atomically under service-owned storage. An HTTP acceptance is the collector's completion boundary: report `uploaded`, not verified inventory ingestion. Do not poll event tokens, read inventory back, query Loki for receipts, or grant extra read permissions just to verify Dependency-Track's internal processing. Internal processing failures remain Dependency-Track's responsibility; its UI failure presentation has not been verified.
7. **Retry carefully.** Use bounded backoff, pagination, expiration handling, timeouts, and single-instance locking. Persist submission tokens promptly and skip accepted uploads after restart. A network failure after server acceptance but before token persistence is inherently ambiguous without server idempotency; document bounded at-least-once resubmission rather than promise exactly-once behavior. Do not advance accepted-upload checkpoints on rejected or failed transfers. Serialize uploads per target and prevent an older run from overwriting a newer inventory.
8. **Private least-privilege operation.** Deploy an unprivileged systemd oneshot with a `Persistent=true` timer, restricted filesystem access, protected scratch space, and only required egress. Runtime credentials come from Ansible Vault/agenix or protected systemd credentials, never Nix values/logs. Use a dedicated SBOM GitHub App, not the Grafana observability App. Configure one App ID, its protected RSA private key, and an explicit array of approved installation IDs across accounts/organisations. Installing this App on all repositories is permitted but does not establish artifact trust. Resolve each configured repository's installation using App JWT authentication and reject IDs outside the approved array. Request a short-lived installation token with that repository ID explicitly supplied and only Actions read (plus GitHub's implicit Metadata read). Keep tokens in memory only and refresh before expiry; subsequent polls mint fresh tokens after restart. Never request a default all-repository/all-permission token. Grant Dependency-Track only required BOM upload/project access. Persist no bearer credentials in checkpoints.
9. **Use existing observability.** Structured redacted journal events flow to Loki; use existing Prometheus/Grafana integration for last accepted upload, backlog age, rejected/expired artifacts, and failures. Distinguish an idle successful poll from an accepted upload; do not claim verified ingestion. Include a recovery procedure for retention gaps and token rotation.

## Risks / Trade-offs

- [Allowed workflow compromised] → Narrow workflow/ref/event policy; optional attestations cannot substitute for that policy.
- [Artifact expires before recovery] → Retention contract, backlog monitoring, and documented deliberate rerun/republication.
- [Timeout creates duplicate submissions] → Skip persisted accepted uploads and disclose the narrow at-least-once crash window.
- [Multiple versions overwrite one another] → Explicit target mapping, ordered per-target processing, and stale-run rejection.
- [Dependency/schema supply-chain risk] → Reuse packaged libraries where appropriate; verify current applicable releases, hash all new dependencies, and apply repository update policy.

## Migration Plan

Validate the producer contract and API upload acceptance/permission behavior with disposable/local fixtures and a dedicated test project. Provision the one production target and least-privilege credentials through existing automation, deploy the collector disabled/report-only for discovery validation, then enable the targeted Habiki timer. Confirm upload acceptance, a no-op repeat poll, restart recovery, malformed artifact rejection, and absence of new ingress. Rollback disables collection and revokes dedicated credentials while retaining checkpoint evidence and existing Dependency-Track data; do not delete projects or uploaded inventories.

## Open Questions

- Select the first trusted repository, workflow/ref/event, artifact name/path, and pre-created project UUID before production activation; never infer them from #26.
- Dependency-Track reports 4.14.5; upload acceptance plus a persisted token is sufficient. Verify supported schema versions and least-required upload permissions, without investigating internal completion further.
- Set polling interval, retention/recovery window, resource bounds, and rolling-versus-release version policy from the first producer's actual cadence.
